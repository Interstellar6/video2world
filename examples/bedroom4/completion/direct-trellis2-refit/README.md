# Bedroom4 direct TRELLIS2 refit source-view evidence

This directory keeps local, hash-bound source-camera evidence for direct
TRELLIS2 scene refits. It has two lightweight evidence sets:

- `pillow-source-view-evidence/`: generated by
  `pillow-source-view-config.json` for `sam3_pillow_front`,
  `sam3_pillow_left`, and `sam3_pillow_right`.
- `source-view-audit.json` plus `views/`: selected source views for refitting
  the existing `nightstand_01`, `nightstand_02`, `plant_01`, and `plant_02`
  object assets.

Neither set edits nor promotes a production world manifest.

## Canonical audit

Each source-view audit is a machine-readable contract. It binds every selected
source RGB, SAM3 mask, camera record, and source 3D anchor by path and SHA-256.

The local cameras.json and the copy under the Holi-Spatial result are
byte-identical:

- SHA-256:
  89f7f4d3855dcf7a439de5556e82c9a5a61d7bc0c274c0289dac496e2d133330
- Rotation convention: camera-to-world.
- Projection:
  camera_points = (world_points - position) @ rotation.

The upstream camera_info.json is referenced and hashed by the authoritative
bed-anchor receipt, but its bytes are not materialized in either local tree.
The audit records this as a gap and uses the verified cameras.json.

## Script-ready view manifests

The top-level `views/` directory contains one minimal loader input per
nightstand/plant object:

- views/sam3_nightstand_01.json
- views/sam3_nightstand_02.json
- views/sam3_plant_01.json
- views/sam3_plant_02.json

Each file declares exactly three frame IDs, a relative observed-mask path with
SHA-256, and is_source_view=true. occluder_masks is deliberately empty because
there is no explicit relation evidence that another same-category object
occludes the selected instance. All four files have been parsed successfully
with fit_completed_object_to_scene.load_view_manifest.

## Selected nightstand/plant evidence

The view selector searches frames 000048 through 000072, chooses the maximum
camera-to-object view-ray baseline pair, and then chooses the frame that
maximizes its minimum angle to that pair.

| Object | Frames | Associated SAM3 files | Max baseline | Minimum selected anchor hit |
| --- | --- | --- | ---: | ---: |
| sam3_nightstand_01 | 000048, 000055, 000063 | nightstand_02.png in all views | 5.234 deg | 0.9053 |
| sam3_nightstand_02 | 000048, 000053, 000062 | nightstand_01.png in all views | 3.518 deg | 0.7820 |
| sam3_plant_01 | 000048, 000061, 000068 | plant_02.png, plant_01.png, plant_01.png | 3.119 deg | 0.8077 |
| sam3_plant_02 | 000048, 000055, 000064 | plant_01.png, plant_02.png, plant_02.png | 4.781 deg | 0.7568 |

SAM3 filename suffixes are per-frame detector ordinals. They are not stable
instance IDs. Each association above is selected by projecting the exact
source 3D anchor into the source camera and comparing its point-hit ratio
against all same-category masks. The JSON retains the selected and runner-up
ratios so a consumer can fail closed.

## Valid use

These three-view sets are ready for:

- rotation, translation, and uniform-scale placement fitting;
- visible width, height, and source-camera silhouette review;
- detecting gross object position and proportion errors.

They are not evidence for:

- a complete back surface;
- top or bottom geometry;
- amodal silhouette recovery;
- a full 360-degree object reconstruction.

The best baselines are only 3.12 to 5.23 degrees. Fit a TRELLIS2 PBR GLB with
rotation, translation, and uniform scale first. Any per-axis correction should
be bounded and reported separately so scene placement does not silently
distort object geometry.

## Reproduction commands

Regenerate the pillow source-view audit and three pillow view manifests:

    uv run python scripts/prepare_multiview_scene_fit_evidence.py \
      --config examples/bedroom4/completion/direct-trellis2-refit/pillow-source-view-config.json

The existing nightstand/plant source-view audit is kept as a local evidence
snapshot. Its four committed view manifests can be consumed directly by
`fit_completed_object_to_scene.py`.

Regenerate the non-generative 1024-square source RGBA conditions:

    uv run python scripts/materialize_source_rgba_conditions.py \
      --config examples/bedroom4/completion/direct-trellis2-refit/source-rgba-condition-config.json

Load-check the four committed view manifests with the same calibrated camera
contract used by scene fitting:

    uv run python - <<'PY'
    import json
    from pathlib import Path
    from scripts.fit_completed_object_to_scene import load_view_manifest

    root = Path("examples/bedroom4/completion/direct-trellis2-refit")
    config = json.loads((root / "pillow-source-view-config.json").read_text())
    cameras = (root / config["cameras"]["path"]).resolve()
    for path in sorted((root / "views").glob("*.json")):
        payload = json.loads(path.read_text())
        views = load_view_manifest(path, object_id=payload["object_id"], cameras_path=cameras)
        print(path.name, len(views), [view["frame_id"] for view in views])
    PY

The commands above are local-evidence commands. They reference hash-bound
Bedroom4 SAM3 masks and source RGB files under the local Video2Mesh/Holi-Spatial
mirror. They do not run TRELLIS2, generate GLBs, carve the static PGSR/TSDF
scene, or promote a production world.
